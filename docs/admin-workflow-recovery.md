# Recover a stopped character run in the admin

Open the order and choose **Open W2A Recovery**. Inspect the existing order; do not import it again or use Force Regeneration to resume a partial run.

For a supported interrupted pose run, **Resume interrupted poses** shows the existing poses to keep and the poses to continue. Confirm that the failure cause has been fixed. **Check resume readiness** verifies the stopped execution, frozen book selection, retained images and job history, then saves a plan without generating images. The confirmation resets when that check changes the order revision.

Review the saved plan, confirm the cause is fixed and acknowledge image-generation credits, then choose **Resume remaining poses**. That is the action that starts generation. It continues at the saved rejected pose and preserves the earlier published images and base character. Open the order to monitor progress. A defective earlier pose can be flagged and regenerated individually during pose review after the continuation finishes.

A reserved continuation cannot be started a second time. If an accepted continuation stops before creating any new pose attempts, the panel offers **Check resume readiness** again. That check verifies the stopped run and its history, unchanged attempt records and original retained image hashes, then saves a fresh plan without generating images. Confirm the cause again and acknowledge credits before choosing **Resume remaining poses**. If the continuation created new attempts, changed retained assets or cannot be verified, it stays held for inspection. If a request has an uncertain outcome, refresh and inspect the current order/execution; do not repeatedly click or reset. The console displays available failure evidence and blocks another dispatch. Some failure shapes cannot be safely continued automatically; they stay held with an explanation rather than silently starting the book over.

For an empty run that failed before any generated assets, the separate resolved-cause retry can queue W2A through the router. For fully completed, verified poses whose parent stopped before closing, **Finalize 2A** returns them to review without generation. These are distinct from partial continuation. Existing stage recovery/regeneration retains its own ownership and review requirements; this change does not enable printing or approve the book.

Regenerate 2A is a full regeneration control. It clears stage assets and is blocked during a W2A failure hold. Use the recovery link beside it for a stopped run.

Deployment note: after a failed continuation has been checked again and its new plan is prepared, keep the updated recovery backend deployed. Earlier recovery code does not understand the archived failure barrier. Do not roll back to that code while such a plan is actionable; first quiesce recovery through a reviewed operational change or finish the user-controlled continuation. No schema migration or workflow export change is needed for this correction.

If readiness fails, the recovery panel shows the error beside its controls and moves focus to that message. The confirmations clear after a request; an unchecked box does not mean no request was attempted. An inspection refresh error does not erase the action error. Successful error-reporting executions are distinguished from generating parent runs: recording a failure must not itself prevent recovery. Unknown or potentially generating newer executions still block readiness.

### All poses exist but accepting a replacement says the book is owned

A final completion callback can fail after the images and manifest are published. Inspect W2A Recovery: an actively claimed W2A row is checked against its reserved execution, including native retries. Sync its verified stopped failure, then use Finalize 2A only when the console proves every frozen pose and canonical image is complete. Neither action generates images. Return to the order and accept the pending replacement, then review the stage normally. Keep active workflow and print locks intact. The manifest builder now carries its validated original parent claim explicitly; native completion no longer needs ephemeral execution custom data. Execution-detail inspection accepts up to32MiB; history/workflow metadata remains bounded at16MiB. Larger records fail closed.
