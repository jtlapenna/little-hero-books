# Storyboard Wireframe Pass 01

## Purpose

This is a simpler, more visual read of the current 30-page plan. It is meant to answer:

- how many existing backgrounds can we reuse?
- how many new backgrounds do we likely need?
- how many existing poses can we reuse?
- how many new poses do we likely need?
- where do animal clues appear?
- does the story feel like a natural book, not a story forced around old assets?

This is still a planning draft, not final copy.

### Personalized Child Poses

| Status | Estimate | Notes |
| --- | ---: | --- |
| Existing pose refs reused | 9-10 unique poses | Mostly dream-world pages from the current pose set. |
| New personalized poses | 4-6 likely | Needed to celebrate the custom child early and carry the ending. |

Highest-value new pose candidates:

- child arriving/excited at the park
- child exploring/choosing at the park
- child looking up at the tall slide
- child in bed with tangled feelings, if current pose 1 does not work
- child at top of slide saying "You go first. I'm almost ready."
- optional dream one-step practice or final landing joy

### Animal / Clue Pages

Core animal-guide presence:

- existing/known animal systems: **3 major beats**
  - tracks
  - animal reveal
  - flying home
- additional pre-reveal clue beats: **6-8 likely**
  - first hidden trace near bedtime/window
  - door clue
  - tracks
  - almost-animal humor
  - nudged sign / quiet path clue
  - cave echo helper
  - dream bridge support
  - near-reveal trail clue

These should mostly be low-cost visual devices: overlays, small props, shadows, tracks, tails, feathers, pawprints, or small animal-only moments.

## Current Honest Read

The core story flow feels natural:

> park fear -> dream practice -> return with self-trust

The previous asset map felt too biased toward avoiding poses. This pass corrects that by making the custom child visible immediately and repeatedly in the opening. Existing assets still help a lot in the dream middle, but the book should not hide the personalized hero to save generation cost.

## Legend

- **BG: existing** = likely current background or current background crop/reuse
- **BG: new** = purpose-built background/visual likely needed
- **BG: conditional** = could reuse existing, but a new visual may be better
- **POSE: existing** = current child pose ref likely usable
- **POSE: new** = new personalized pose likely worth generating
- **POSE: none** = no main personalized child needed
- **ANIMAL** = animal, clue, track, or guide presence

## What This Suggests

This plan is not all-new, and it is not asset-forced.

The new material is concentrated where the story now needs it most:

- personalized hero introduction
- tall slide setup
- top-of-slide anxiety
- bedtime transition
- too-many-voices mechanics
- dream height mirror
- return-to-slide climax
- final exercise/end matter

The existing assets are doing useful work in the dream middle, where their magical tone still fits the story. The old assets should support the new story, not dictate it.
