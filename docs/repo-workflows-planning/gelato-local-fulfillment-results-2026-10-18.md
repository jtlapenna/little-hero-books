## What changed

- Approval, rejection and structured correction now use one service-only database transaction for the order snapshot and token consumption. Busy W3, missing/unreviewed previews, stale snapshots and competing links fail closed. A failed database call leaves the link retryable; there is no split-write fallback.
- Canonical Gelato claim and submission check current customer approval. The proposed migration adds a row-locked guard at initial/retry ownership acquisition and a final send guard. Revoking approval cannot prevent safe fencing or read-only uncertain-outcome recovery after a send was authorized.
- Ordinary cron holds Gelato work while draft submission is OFF, holds unknown providers and existing submissions, and counts complete modern, legacy-Amazon and root-inclusive sibling groups. Incomplete candidate windows and insufficient capacity hold the whole group. The aggregate path obeys the same gates.
- W1’s exported classifier reads current approval/ownership/W3 fields and holds unready groups. Its claimed Gelato envelope now carries canonical book, format and config metadata required by the actual W4 PDF handler. No hosted workflow was imported or activated.
- A **read-only** release-review helper prepares account/cohort, current approval, destination, product, quantity, file hash, quote freshness and shipping checks. It always returns `canRelease:false`. There is no new conversion executor or regular-order submission route. Product line prices are aggregated once; quantity two is explicitly tested. Unknown taxes, fees and payable total stay unknown, and paid approval remains required.

## Validation and limits

Eighteen selected test commands passed, including 14 component/producer/route commands and four extended integration/SQL/Worker commands. Independent reviewers reran the important suites and found the routing, alias and recovery defects described above; those findings were fixed and rechecked. An additional optional dummy-PDF byte benchmark also passed under the current dependency lock, with 16 measurements. Its buffered Worker bridge is a local estimate, not deployed timing, billed CPU, final-artwork throughput or a full three-candidate batch. Do not add overlapping assertion counts into an inflated total.

The SQL runs used disposable PostgreSQL 17 containers with no network, published ports, customer-data mounts or persistent volume. Each owned container was removed. Original fulfillment migrations were applied twice, the new migration twice, and actual existing RPC implementations exercised. The service-role preview test explicitly models established order UPDATE rights; it does **not** attest hosted schema, RLS or grants. The native macOS initdb attempt failed shared-memory allocation, so cached official Docker PostgreSQL was used without changing system database settings.

The repository-wide typecheck is not green: matching baseline and current source each report 353 diagnostics by file/code count. Retained generated `.next` validators add 35 diagnostics locally (388 total). No new source diagnostic was introduced; full deployment build and hosted CI were not run. An archived source baseline omits generated validators, so that comparison does not prove their generation is clean.

The positive connected journey uses an in-memory active clone of bundled v2, which remains **draft** on disk. Dummy images replace image generation; post-PDF administrative approval and database/R2/Gelato transports are simulated. It runs exported native Code/expression nodes and actual backend HTTP handlers, not the hosted n8n engine. Atomic SQL is independently tested rather than reached through real PostgREST. This is connected local engineering proof, not complete live end-to-end proof or creative approval.

Only fake process-local bindings are briefly set true for positive synthetic branches and restored OFF. All nonintercepted fetches throw. No live ON window occurred, so no live restoration was needed. The last historical OFF receipt remains dated `2026-10-18T05:01:13.115Z`; it is not a fresh live-state attestation.
