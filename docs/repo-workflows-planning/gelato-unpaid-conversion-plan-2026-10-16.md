## Problem and bounded behavior

The normal W4/W4.1 path explicitly creates held Gelato drafts. It has no regular fulfillment operation. This change preserves that default and adds one internal, bearer-authenticated endpoint for an exact operator-created authorization. It patches an existing verified draft with only `{orderType:"order"}`; it never creates an order, supplies payment, cancels, sends a customer message or changes ordinary flags/routing. Gelato's [draft patch contract](https://dashboard.gelato.com/docs/orders/v4/patch/) retains items/files when omitted. Real identity and original file bytes must still match after conversion; no global mapping relaxation is added.

The service-only table binds one native submitted TEST-GELATO root, its complete one/two-child membership, provider root/item IDs, artifact keys/PDF SHA-256s and the SHA-256 of the actual runtime API key. A fresh owner/dashboard funding attestation and private receipt hash expire within fifteen minutes. Funding inspection is a trusted operator input: SQL cannot prove that no third party later funds the account. Do not treat card absence or an authorization row as proof of provider billing safety. Recheck all wallets, auto-topup, plan/invoice and alternate-credit routes immediately before each case. Stop if there is any funding or active-work conflict.

Each authorization is unique for its submission/provider root and cannot be replaced to retry. The database owns the preparing/sending claim, exact token, irreversible send marker and closed timestamp. Canonical root locks serialize transitions; expiry/context checks occur after lock waits, including direct service-role transitions. Service role cannot edit descriptors, expiry, members or reopen/delete the row. Helpers are security invoker with fixed search paths; no anon/authenticated access is granted. This is an operator accident/retry boundary, not a defense against a malicious database administrator who already controls canonical data.

The runtime requires explicit credentials and all five process flags strictly false; SQL additionally requires ordinary dispatch false. Actual canonical PDF bytes, saved request URLs, recipient/product/page counts/service, connected graph and provider original file bytes are checked before the one PATCH. A fresh real quote must select the saved exact method. Fetch/body deadlines bound provider and artifact reads. The authorization closes even on begin/validation/factory failure; an independent operator close is still required if the process dies. An uncertain PATCH is never retried. GET-only observation reconciles the original provider root after closure. Converted orders are not automatically canceled, and funding must not be restored while unapproved regular test orders remain capable of release.

Raw provider responses can contain private shipping details. The internal endpoint returns them only to the bearer-authenticated operator with no-store headers, for immediate owner-only local preservation. They are never logged or passed to frontend/customer consumers. Public evidence is an explicit allowlist of statuses, amount fields, identity/file hashes and request/response hashes. Existing admin/lifecycle refresh remains responsible for application status; this release does not add a financial dashboard or claim that simulated webhooks establish real provider delivery.

## Rollout and operator sequence

1. Fetch current main, preserve unrelated work, review the exact staged diff and direct producers/consumers. Require independent SQL and application review, exact CI/preview checks, migration/source identity and redacted evidence review. Publish native results as dated draft-only evidence.
2. With all normal controls OFF, install only `migration-gelato-engineering-conversions.sql` using the authorized Supabase connection. 3. Merge the reviewed application release, wait for its authoritative production deployment and verify serving SHA plus all normal OFF controls, no unexpected open windows/auths, inactive original/dedicated workflow copies and zero customer sender activity.
4. Build/review a protected operator with exclusive, fsynced per-effect intent records, actual source/key pins, exact known roots, fixed request allowlists and a standalone closure helper. It may insert one fresh authorization for each already proven native draft and call the internal endpoint once. No generic provider create/patch/cancel route is permitted in the operator.
5. Immediately before each case, recheck the signed-in account and every funding route, save evidence privately and bind its fresh timestamp/hash. Recheck canonical/provider file hashes and intended tier. Open only the exact conversion authorization; preserve raw response text and hashes before parsing. No normal gate or workflow activation is needed for this step.
6. Observe the exact provider response and same root. Record acceptance, payment-required/failed/held state, available file processing and quote/order amounts honestly. Stop further cases on any funding/production anomaly. Reconcile uncertain outcomes with GET only. Scoped existing refresh/poll/status handling must preserve exact mappings and produce zero customer intents; label simulated events separately.
7. Close all exact authorizations, hold fixture rows, verify no native windows remain open, all owned copies inactive and all ordinary controls OFF after each case. Preserve private originals and publish allowlisted results/reproduction. Inventory unapproved regular test orders before any future funding change; do not restore payment to release them.
