# Local Gelato queue and polling isolation

This phase implements the local engineering boundary identified by the [read-only workflow audit](gelato-live-prep-audit-2026-10-19.md). It does not install a migration, publish/activate a workflow, deploy, change hosted controls, access any live order, fund an account, print, convert an order or send a customer message. The six pending orders were not selected or read. All service transports in tests are intercepted; disposable PostgreSQL contains invented fixtures only.

## Result and design

The normal queue and cron retain their OFF behavior. A new privileged **manual engineering endpoint**, `POST /api/internal/w4/engineering-isolation`, accepts only `{scopeId, action}` where action is `queue`, `register-status`, `status` or `close`. It requires current backend machine authentication plus a separate 256-bit capability supplied in `x-lhl-engineering-token`. No client may pass IDs, roots, account overrides, provider destinations, enable flags or arbitrary operations. Malformed requests fail before runtime construction.

The new migration `20261020011248_gelato_engineering_isolation.sql` creates an empty service-only scope table with RLS and invoker functions. No existing order is enrolled. A scope is tied to an existing reviewed engineering window, one fresh TEST-GELATO root, its exact one/two children, account-key digest, fixture-manifest digest and deadline of at most 30 minutes. Minting refuses any root with a prior submission or submitted child, even if its name starts TEST. The scope cannot be reparented, re-keyed, extended, reopened or have its budget reset. No HTTP issuer exists: future scope creation remains a protected, specifically approved service-role operation.

The queue reuses canonical W0 routing and the existing native queue core. A server-only admission hook permits this exact cohort while the shared draft flag stays OFF; existing-submission, approval, completeness and ready-state checks still apply. Rehydrated rows and roots are checked again before reading manifests or group members. The scoped SQL wrapper consumes one queue claim under the root lock and binds the resulting submission once. Replays and lost responses do not redispatch. This path cannot create or convert a provider order itself.

After a fresh draft is recorded, an explicit `register-status` action can enroll only that exact scope-bound submitted draft. The existing scheduled worker uses dedicated scoped claim/apply/hold/finish RPCs and a separately configured status key resolving the same account digest. Three polling leases total are permitted for the scope. Registration replay cannot replenish them. Ordinary polling excludes scope-bound submissions even if someone uses the ordinary registration function and leaves its scope column NULL. This intentionally narrow version accepts one saved provider root per scope. Unexpected connected roots or a multi-root provider split are held for separate review; they are not silently fetched or treated as tested. Split parcels within one order do not broaden the saved-root allowlist. There is no historic-order selector, search, recovery/create, cancellation or message sender in the isolated polling path.

All six shared flags must be explicitly false for active work, and both normal database gates must be OFF. The ordinary cron still uses `CRON_SECRET` and still returns disabled while OFF. The isolated timer caller instead needs both backend machine authentication and its dedicated expiring scope capability; the backend token alone is insufficient. This does not claim the normal enabled cron has been verified.

Each provider GET, provider file GET and R2 file read rechecks the scope and OFF state before transport. Polling time is bounded by scope expiry; stored-file host, redirect, grant, receipt and byte checks remain in force. Scope validity is rechecked after blocking status writes, rolling back a late mutation if authority expires. Closing works after expiry/account rotation/control drift, closes the parent window, disables only the exact bound registration (including a wrong-path registration), clears its lease and cannot reopen it. An already-started read may finish under its existing abort deadline after closure; no future read or SQL update is authorized by that old check.

## Verification

The new actual-route/disposable-PostgreSQL suite passed **26 named checks**. It includes three cases: website single, Amazon single and two-child Amazon siblings. Queue output is fed through the actual native workflow's `Prepare Gelato Request` code for single/sibling parsing. The actual HTTP route, canonical W0 resolver/claim, scoped SQL and registered polling runtime are exercised. Provider snapshots/file responses and draft persistence are synthetic; this is not hosted n8n/W4 or Gelato prepress proof.

Covered failures include both database gates and each of six env controls ON; bad machine/capability/schema; changed test mode; approval revoked after TS preflight; concurrent reparenting; historical TEST roots; two workers competing for one claim; a committed response lost; wrong-path registration; rate limiting/Retry-After; swapped sibling file bytes; expired/reclaimed polling leases; exhausted persistent budget; closure with an active lease; and anonymous/authenticated-role access denial. A real two-session SQL write was held across scope expiry and all its changes rolled back. Six fabricated historical child rows remained byte-identical, with zero notification intents. They are not the six live orders; those were never queried.

The ordinary queue (44 checks), existing seven-job scheduler/deadline suite, stored-file checks, actual automation runtime/Worker suite and default-deny access-boundary suite passed. The retained three-case combined dummy-PDF/release/scheduler/admin regression is rerun on the new empty isolation schema and reported in the evidence package. Its synthetic regular-order conversions do not contact a provider or authorize real conversion.

Full typecheck still reports **389 existing diagnostics**, with none in changed/new TypeScript files. This is not a green full typecheck. Local Worker build and redacted scanner results are recorded separately. CI is prepared to rerun the isolation suite and combined journey with the new schema. Historical PR34 evidence is preserved; its verifier runs without claiming current source parity, and this new package binds the current implementation hashes instead.

Independent SQL and TypeScript review found expiry-after-lock, wrong-path enrollment and initially vacuous upgrade-test gaps; these were verified, fixed and regression tested. Primary review also added the canonical rehydration guard. No confirmed High/Medium finding remains. Review and tests are local, not release approval.
