## Server boundary

`migration-gelato-scoped-engineering-windows.sql` adds an empty-by-default service-only window table. One root binds one/two exact sorted child database IDs, an account-key digest and private evidence metadata. Root and every child must be TEST-GELATO identities, every order must currently have object-shaped testMode true, the complete root membership must match, and the frozen assignment must be Gelato v2+ with 35 upload pages. Opened/expiry timestamps limit an entry to 30 minutes. No global gate or environment value is changed.

Service role can insert a window, read it and close it once. It cannot extend expiry, change members, delete it or reopen it. Anonymous/authenticated roles cannot read the table or call the helpers. RLS is enabled; functions are security invoker with fixed search paths. No public-policy allowance is added.

The normal claim/begin/send functions keep their existing checks. A scoped alternative is evaluated only for that complete cohort. Gate SHARE, root advisory and submission locks keep the canonical order; scoped expiry is checked after blocking locks. Claim lease, quoted-request fingerprint, saved explicit draft mode, frozen recipient/files/items, send-once and ambiguous-outcome fencing remain enforced. The actual runtime checks the exact key digest used by its provider client before allowing a scoped draft while its ordinary draftsEnabled diagnostic remains false. Missing key, missing/expired/closed authorization, nonboolean RPC response or unavailable database fails closed.

The account digest binds the canonical runtime entry. SQL begin/send intentionally do not independently authenticate a provider account. The fixture digest is audit metadata, not database enforcement of PDF bytes. The protected runner must compare approved source hashes, canonical output PDF hashes/bytes and provider item/file associations independently. Those facts must not be inferred from a window entry.
