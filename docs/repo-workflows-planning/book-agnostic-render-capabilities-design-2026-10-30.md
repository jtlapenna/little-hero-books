## Version and schema

Add recipe discriminator lhb.book-render@v3 to the existing recipe schema. Retain v1 parsing and rendering byte behavior. Existing uncommitted v2 flow remains a preserved working-tree branch and a later explicit adoption; clean v3 must not import its flow runtime. This is a new capability version in the same renderer, not another rendering engine or registry.

V3 recipe fields reuse pagePreviewTemplateId, poses and animals. Copy maps accept one block or an ordered array of at most 20 blocks per page. Covers retain backgroundSlot, templateId, layers and texts, and may add bounded stacks. New recipe, typography, fit, layout and stack objects are strict. Unknown discriminators, properties inside new capability objects, enum values, nonfinite numbers, invalid references and unsupported combinations reject before asset construction, output writes or transport. Historical outer config metadata keeps its existing parsing behavior.

New v3 capability fields on page/cover layer placement are optional and have no parse-time defaults: layout is a strict object with required units (px or percent), referenceCanvas (w,h positive finite), rounding (none or nearest), anchorXPercent/anchorYPercent and originXPercent/originYPercent (0 through 100), and scale (positive finite, at most 10). Reference canvas and rounding are allowed only with px units; rounding requires a reference canvas. Layout is rejected by recipe validation for non-v3 recipes. Old placements without layout use the existing implementation unchanged. The outer page-layer schema must retain the known layout object for version-aware validation; it must not silently strip it.

V3 copy requires unique block IDs per page/cover, text, placement, fontSize, lineHeight, color, align and padding. Its typography object permits trackingPx (-20 through 100), verticalAlign (top, center, bottom), wrap (pre-line, balanced, single-line) and case (none, uppercase). Center/bottom alignment and fit require an explicit positive box height. Line height permits 0.5 through 4, including Amazon 0.96. Fit is an optional strict single-line policy with minFontSize, optional softMinFontSize and maxFontSize; all are positive finite, min <= softMin <= max <= 512. Fit requires single-line wrap. No character-count estimate substitutes for measured fitting.

V3 optionally declares ordered fontRoles, one to four unique aliases from config.assets.fonts. Omission means primary only. Every referenced role must resolve to a validated key in the selected book namespace. Generate one shared font family with ordered source URLs; do not hardcode first-book aliases or claim a fallback font proves byte equivalence.

## Placement and calibration

Resolve the selected format canvas before placement. With px referenceCanvas, multiply left/width by canvas.w/reference.w and top/height by canvas.h/reference.h. Round each computed dimension once only when nearest is selected. This expresses legacy interior 2550-to-2625 rounding, including overrides. Percent units express left/top/width/height against the current canvas. Percent units reject referenceCanvas and rounding. Scale does not modify stored measurements.

For v3 placements with an explicit layout object, compose transforms in fixed order: anchor translation, rotation, uniform scale and optional horizontal reflection, around explicit origin percentages. Defaults within the v3 renderer are zero anchor, zero origin and scale one. First-book sprite config chooses bottom-center anchors and center rotation explicitly; cover config carries its existing 86.5/80.5 sprite anchor. Layout presence selects the new transform semantics. An absent layout uses the old transform implementation even in v3, including the existing rotate, width translation and reflection compensation. An explicit layout with units:px opts into the documented zero-anchor/zero-origin defaults. An empty layout rejects because units is required. Test these cases separately. Keep old recipe transform ordering unchanged. Config authoring must convert legacy post-scale translations into equivalent explicit positions and verify the resulting matrix rather than approximating it.

Existing character/animal/cover override paths remain canonical. The interior/animal clone projections currently drop anchors. Add a version-aware optional parser/resolver mode that preserves and validates anchors for v3 while keeping the old default mode unchanged. Select that mode from frozen recipe context in W3 and calibration, never from an untrusted standalone request flag. Reject anchor overrides on a v3 layer without an explicit layout rather than silently ignore them. Merge only defined override values into a layer, carry anchor values into v3 layout, and apply the reference-space conversion after merging. First-pose/first-animal editability remains unchanged. An override must not discard layout metadata, leak an interior reference space into the cover or double-scale values. Tests enter the actual calibration request builder and buildW3PreviewPlan, not only renderer options or a CSS helper.

## Copy, guides and cover flow

Use existing animal-role mapping for trails. A trail is an animal layer with role trail; all eight guide mappings must exist and stay inside book namespace. Five trail variants can share keys through those mappings. No new guide-background table is needed for this first-book requirement.

Add v3 copy tokens child name possessive and hometown return. Possessive uses a trailing apostrophe for names ending in s, otherwise apostrophe-s. Hometown return is to plus supplied trimmed hometown, otherwise back to their cozy town, matching the legacy conditional. Interpolate plain values once, then escape HTML. The storyTexts projection must flatten ordered copy arrays in the same order with newline separators; it must not read .text from an array or drop nested cover copy. storyTexts remains page-only, with no added cover record. The cover proof extracts DOM text in tree order from the serialized cover payload; no new cover metadata field is introduced. W0/W3 tests assert projections and request payloads together with rendered text. Dynamic text must not become markup, CSS or script. Preserve line breaks. Keep old recipe token acceptance unchanged; reject new tokens outside v3. Existing shared BOOK_COPY_TOKENS validation must select the version-appropriate set.

Adopt the existing untracked book-pronouns.ts helper byte-for-byte only after reviewing its source and callers. V3 uses canonical exact-word pronouns, with explicit they/them correction compared with the historical baseline. Do not change the historical legacy W3 parser or old configured v1 branch in this phase. If the composed working tree already has broader pronoun changes, preserve them as excluded source, not part of this candidate.

Cover stacks are optional, at most eight roots. A root has a unique ID, absolute placement and child nodes. Node kinds are text and stack only. A text node reuses the v3 text/style primitive without absolute placement. A nested stack may set width, padding, spacingBefore, spacingAfter, gap, alignment and a frame. Numeric spacing is nonnegative and at most 2048; widths are positive and bounded to 100000. A frame has validated hex border color, border opacity, border width and radius, never raw CSS. Opacity applies to the border only, not child text. Padding uses explicit top/right/bottom/left values; child centering and start/center/end alignment are explicit. Limit depth to four and total cover nodes to 64. Text IDs are unique across flat cover text and nested nodes. No node references, cycles, arbitrary HTML, style strings, scripts or layout callbacks.

Render stacks as normal column flow using the same text primitive as absolute copy. Disable margin collapse; explicit spacing and padding produce the result. Root scale/origin and typed nested frames express first-book back-title, body, try heading, bordered panel and footer. Config authoring owns measured equivalence to the saved SCSS. Convert effective collapsed margins into explicit noncollapsing spacing instead of summing copied margin values. Record each conversion with the resulting DOM measurements. This is bounded document layout, not a generic component system.

## Measured fitting and execution envelope

Use one audited static browser routine for v3 single-line fitting. Use v3-specific data attributes and status names. Never emit the saved legacy template selector data-fit-mode="single-line" for v3, so its independent emergency-minimum fitter cannot override v3 policy. Each generated document installs one idempotent routine, not a competing pass for every text node. It takes only rendered data attributes and DOM measurements, never config code. Wait for configured font sources and document.fonts readiness, run two animation-frame passes, shrink in one-pixel steps through the configured minimum, then inspect width and height. Mark each target fit, soft-min-exceeded or overflow. Missing fonts, zero dimensions or remaining overflow produce an explicit failure state. Expose a completion promise and root status so headless proof consumers await the actual result rather than a delay. Escape all dynamic content; embed no user strings in executable source.

The existing saved hosted cover-fit template remains frozen. Local v3 HTML must include its reviewed static fit routine and readiness contract so the same generated HTML is exercised by headless review. Phase008 must reconcile actual PDFMonkey execution of that envelope before hosted acceptance. Lack of hosted execution is a disclosed hold, not a local fitting pass. Do not silently replace the historical emergency minimum or font fallback behavior in old recipe output.
